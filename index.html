Promise resolution / live experiment

When does the getter run?

Resolving a promise can run your code before the caller returns. SafePromiseResolve moves that work to a microtask. Watch a then getter change position in the execution order below.

Open the Web Console before running. In Firefox, press Ctrl+Shift+K (macOS: ⌘⌥K). A build with the warning patch should report reordering once per page load. This demo uses a stream’s start() return value; Firefox builds with that SafeResolve path do not need the experimental pref.

The code that triggers safe resolution 
const thenable = {
  get then() {
    console.log("then getter");
    return resolve => resolve();
  }
};
new ReadableStream({
  start() {
    return thenable;
  },
  pull(controller) {
    controller.close();
  }
});
console.log("constructor returned");

Ordinary resolution reads then synchronously, though it calls the returned function in a microtask. Safe resolution defers the getter too. The page observes this order directly; it cannot inspect Firefox’s native console warning or read browser preferences.

No dependencies, network requests, or build step. Thenable curtailment proposal.
